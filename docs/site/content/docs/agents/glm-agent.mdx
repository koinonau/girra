GLM-5.2 works in Girra through the agent harness you already use. Configure GLM-5.2 in Claude Code, OpenCode, or another CLI agent, then launch that agent from Girra's picker.

Girra supplies the isolated worktree, terminal panes, browser tab, review flow, and session management. Your [Z.ai CodePlan subscription](https://z.ai/subscribe) and agent config supply the model access.

<Callout title="Prerequisite">
  You need an active [Z.ai CodePlan subscription](https://z.ai/subscribe) with GLM Coding Plan
  access before configuring GLM-5.2 in an agent harness. OpenAI-compatible harnesses also need a
  Z.ai API key. Girra does not include or resell GLM access.
</Callout>

<Callout title="Source">
  This page documents the GLM-5.2 configuration tested with Girra. Z.ai's [model
  guide](https://docs.z.ai/devpack/latest-model) may list newer models; verify model names, context
  limits, and harness compatibility there before substituting one.
</Callout>

## Claude Code

Claude Code reads model overrides from `~/.claude/settings.json`. To use GLM-5.2 in Girra:

1. Open `~/.claude/settings.json`.
1. Add or update the `env` block below.
1. Restart Claude Code sessions in Girra so the new environment is loaded.
1. Run `/status` inside Claude Code to confirm the active model.

```json
{
  "env": {
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "1000000",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-4.5-air",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.2[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.2[1m]"
  }
}
```

Use the `[1m]` suffix when you want GLM-5.2's 1M context variant, and keep `CLAUDE_CODE_AUTO_COMPACT_WINDOW` set to `1000000` so Claude Code's compaction window matches that context size. If Claude Code says the `[1m]` model does not exist, update Claude Code and try again.

For coding tasks, Z.ai recommends setting Claude Code effort to `max` with `/effort`. Claude Code's lower effort settings map to GLM-5.2 high effort, while `xhigh`, `max`, and `ultracode` map to GLM-5.2 max effort.

## OpenCode

For agent harnesses that expose an OpenAI-compatible provider:

1. Open the harness settings outside or inside Girra.
1. Choose the OpenAI-compatible provider option, or the Z.ai provider option if the harness has one.
1. Set the base URL to `https://api.z.ai/api/coding/paas/v4`.
1. Add your Z.ai API key.
1. Set the custom model name to `glm-5.2`.
1. Set context window size to `1000000` if the harness exposes that field.
1. Disable image support unless the harness specifically documents image support for this provider path.

After saving, launch the harness from Girra's agent picker. Girra will run the same configured CLI in the selected worktree.

The key rule is simple: configure GLM-5.2 wherever the harness stores provider/model settings, then let Girra launch that harness in the right worktree.
